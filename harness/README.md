# harness — 전역 행동 계약 (global CLAUDE.md)

모든 작업에 걸리는 **행동 계약**을 명시한 하네스다. Claude Code는 세션 시작 시 `~/.claude/CLAUDE.md`(전역)와 프로젝트 `CLAUDE.md`를 컨텍스트에 주입한다. 코드 생성 뿐만 아니라 문서 작업 등 클로드를 활용한 업무 수행시 "**어떻게 일하라**"를 못 박아, 매 요청마다 반복되는 LLM 실패를 구조적으로 줄인다.

## 왜 CLAUDE.md 층인가

- **시스템 프롬프트로는 못 바꾼다.** 모델 기본 행동은 사용자가 편집할 수 없다. CLAUDE.md는 사용자가 소유·버전관리하는 편집 가능한 행동 레이어다.
- **전역 vs 프로젝트로 분리.** 모든 작업에 적용되는 기본 공통 사항은 전역에, 특정 작업 규칙은 프로젝트 CLAUDE.md에 둔다. 병합되어 함께 적용된다.
- **매 세션 자동 주입.** 규칙을 매번 다시 설명할 필요가 없다 — 계약이 항상 컨텍스트 맨 앞에 있다.

## 각 단계가 막는 실패

행동을 "좋은 말"이 아니라 **단계별 계약**으로 고정했다. 코딩을 Plan → Execute → Evaluate → Commit 4단계로 돌리고, 각 단계를 특정 실패 모드의 방어막으로 설계했다.

| 단계          | 막는 실패 모드                                                          |
| ------------- | ----------------------------------------------------------------------- |
| Plan (계획)   | 지레짐작 → 엉뚱한 구현, 그리고 약한 성공기준 → 나중에 검증 불가        |
| Execute (실행)| 요청 없는 추상화·무관 코드 "개선"(과설계·scope creep), 계획 없는 즉흥 실행 |
| Evaluate (평가)| 검증 없이 "완료" 선언 → 실제로는 미완                                  |
| Commit (커밋) | 승인 없는 임의 스테이징·커밋, 형식 제각각이라 읽기 힘든 히스토리         |

**두 개의 제어 게이트:** (1) *no plan, no code* — 계획이 없거나 작업이 계획에서 벗어나면 실행을 멈추고 계획 단계로 되돌린다. (2) *commit approval* — `git add`/`commit`/`push`는 형식(`type(scope): subject`)을 갖춘 초안을 보여주고 승인받은 뒤에만 실행한다.

## 트레이드오프

- 이 계약은 **속도보다 신중** 쪽으로 편향돼 있다. 사소한 작업엔 과할 수 있어, 상단에 "trivial 작업엔 judgment"를 명시해 escape hatch를 뒀다.
- 성공 신호: diff에 불필요한 변경이 줄고, 과설계로 인한 재작성이 줄고, 확인 질문이 실수 **뒤**가 아니라 **앞**에 온다.
