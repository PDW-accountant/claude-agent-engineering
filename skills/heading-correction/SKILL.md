# LLM-Parsed 마크다운 헤딩 교정

PDF에서 LLM으로 파싱한 회계기준 마크다운은 헤딩 계층(H1~H6)이 자주 틀린다. 텍스트만 보면 판별 불가능한 케이스(특히 H3 소절 vs H4 라벨)를 **PDF 원본의 시각 신호**로 확정해 교정하는 스킬이다.

> **핵심 방법: 텍스트가 애매하면 PDF를 이미지로 변환해 실제 레이아웃을 보고 판별한다.** 아래 "H3 소절 vs H4 라벨 구분"이 이 스킬의 심장이다.

## 1. 헤딩 계층 규칙

> **H4 판단 순서 (이 순서를 먼저 적용, 아래 표보다 우선)**
> 1. "H3 소절 vs H4 라벨 구분" 섹션의 **ch12 p9 예시**("재취득한 권리", "주식기준보상")처럼 문단 바로 위에 붙어 빈 줄 없이 이어지는 제목인가? → **H4 라벨**
> 2. 위 조건이 아니더라도 **문단 번호**(19.1, 실19.13, 결19.1 등)인가? → **H4**

| 레벨 | 대상 | 예시 |
|------|------|------|
| `# (H1)` | 제N장 제목. 부록 장 마커(`**일반기업회계기준 제N장 '...'의 부록**`) | `# 제11장 무형자산` |
| `## (H2)` | 제N절, 용어의 정의, 부록 절 마커(`**...의 제M절 '...'의 부록**`) | `## 용어의 정의` |
| `### (H3)` | thick underline 소절, 결론도출근거·실무지침·적용사례, **용어의 정의 내 각 용어 항목**, **개별 사례 레이블(사례 N)** | `### 사례 1` |
| `#### (H4)` | 문단 번호(14.3, 실14.1 등), 단일 문단 바로 위 라벨, **사례 내 하위 레이블(\<배경정보\>, \<회계처리\> 등)** | `#### 14.3`, `#### <배경정보>` |
| `##### (H5)` | H4 라벨 아래 문단 번호, H4 문단 번호의 하위 항목 (⑴, ⑵) | `##### (1)` |
| `###### (H6)` | H5 하위 항목 | `###### (가)` |

**핵심 주의사항:**
- 용어의 정의 내 용어들: `**bold**` 아님, `### 용어명` (H3)
- 비절 `##` (제N절/용어의 정의/부록 아닌 것) → `###` 로 내림
- thick underline(굵은 수평선): 결론도출근거·소수의견·실무지침·적용사례 등 **부록 특별 섹션** 제목 아래에만 존재 → H3
- 테이블 형식 용어의 정의(ch8처럼) → 그대로 유지

## 2. H3 소절 vs H4 라벨 구분 (PDF 시각 기준) ← 각 장 작업 시 반드시 확인

**핵심 규칙: PDF에서 제목 아래에 한 줄 빈 공간이 있으면 H3, 없으면 H4**

이 구분은 텍스트만으로는 불가능하다. 마크다운 파서가 빈 줄 정보를 날려버리기 때문에, **PDF 원본의 레이아웃을 직접 봐야** 확정된다.

### H3 소절 — 제목 아래 빈 줄 있음

위치가 왼쪽에 붙어있거나 탭 들여쓰기여도 아래에 빈 공간이 있으면 H3.

```
회계처리              ← 왼쪽 붙음, 아래 빈 줄 있음 → H3
                      ← 빈 줄
12.7 취득자는 ...
12.8 ...

취득자의 식별         ← 탭 들여쓰기, 아래 빈 줄 있음 → H3
                      ← 빈 줄
12.9 ...
12.10 ...
```

### H4 라벨 — 제목 아래 빈 줄 없음

```
재취득한 권리         ← 빈 줄 없이 바로 이어짐 → H4
12.25 취득자는 ...

주식기준보상          ← 빈 줄 없이 바로 이어짐 → H4
12.26 ...
```

### 요약 비교

| 구분 | PDF 시각 특징 | 헤딩 레벨 | ch12 예시 |
|------|--------------|-----------|-----------|
| 소절 | 제목 아래 **빈 줄 있음** (위치 무관) | `### ` (H3) | 회계처리, 취득자의 식별, 취득일의 결정 |
| 라벨 | 제목 아래 **빈 줄 없음** (바로 이어짐) | `#### ` (H4) | 재취득한 권리, 주식기준보상 |
| 부록 특별 섹션 | 제목 아래 **굵은 수평선** | `### ` (H3) | 결론도출근거, 실무지침 |

## 3. 처리 순서 (반드시 지킬 것)

> **각 장 작업 시작 전 이 SKILL.md 전체를 읽을 것. 특히 §2 "H3 소절 vs H4 라벨 구분".**

1. **PDF 전체 페이지 변환** (아래 §5 명령)
2. **모든 페이지 시각 확인** — H3/H4 구분은 **제목 아래 빈 줄 유무**로 판별 (일부 페이지만 보지 말 것)
3. **헤딩 전체 목록 스캔** (`grep -n "^#" 파일명`)
4. **수정 적용**

## 4. 특수 케이스

**부록 마커 3가지:**
- `**일반기업회계기준 제N장 '...'의 부록**` → `# 제N장 ...`
- `**일반기업회계기준 제N장 '...'의 제M절 '...'의 부록**` → `## 제M절 ...`
- `**부록A. 적용보충기준**` 등 라벨 형태 → **줄 자체를 삭제** (헤딩으로도 만들지 않음. 냅두면 앞 문단의 content에 흡수되어 노이즈가 됨)

**결론도출근거·실무지침·적용사례 컨테이너 승격 (선택, 명시 지시 시에만):**
- 사용자가 특정 장/페이지 범위에 대해 명시적으로 "승격"을 지시한 경우에만 적용 (전체 장 일괄 금지)
- 컨테이너 H3 헤딩(`### 결론도출근거` 등)은 유지하고, 그 아래 모든 자식 헤딩만 **한 단계씩 일괄 승격**
  - 예: `#### 실11.2`(H4) → `### 실11.2`(H3), 그 하위 `##### (1)`(H5) → `#### (1)`(H4)
- 이 승격은 "문단번호=항상 H4" 기본 규칙보다 **우선**한다. 단 명시 지시가 없으면 기존 컨테이너(H3)+문단번호(H4) 구조 유지.
- **사례N 하위 항목 레벨 제약:** `사례1`이 H3이면 그 하위(`<사례> ...`, `(1)~(N)` 등)는 반드시 H4 이하여야 한다.

## 5. PDF 변환 명령

```python
# 단일 챕터 전체 변환
uv run python -c "
from pdf2image import convert_from_path
import os
fname = 'data/raw/제N장_XXX.pdf'
pages = convert_from_path(fname, dpi=150)
base = fname.replace('data/raw/','').replace('.pdf','')
for i, p in enumerate(pages, 1):
    p.save(f'data/raw/{base}_p{i}.png')
print(f'done: {len(pages)} pages')
"
```

## 6. 흔한 실수

| 실수 | 올바른 처리 |
|------|------------|
| 용어의 정의 항목을 `**bold**`로 변환 | `### 용어명` (H3) |
| `**부록A. 적용보충기준**`을 `# 제N장`으로 변환하거나 그대로 냅둠 | 줄 자체를 삭제 |
| `### 용어의 정의`만 `## 용어의 정의`로 바꾸고 내부 용어는 안 바꿈 | 내부 용어도 `###`로 변환 |
| PDF 안 보고 H3/H4 라벨 여부 판단 | 반드시 PDF 시각 확인 후 결정 |
| 일부 페이지만 PDF 확인 | 전체 페이지 확인 |

모든 장 작업 완료 후 한 번에 커밋 (중간 커밋 없음).
