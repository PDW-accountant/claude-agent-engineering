# heading-correction — 시각 검증 루프로 안정화한 정밀 반복작업 스킬

회계기준 PDF를 LLM으로 파싱한 마크다운의 **헤딩 계층(H1~H6)을 교정**하는 스킬. 33개 장에 걸쳐 반복되는 정밀 작업을, 사람의 판단을 스킬로 코드화해 일관되게 수행하도록 설계했다.

## 문제

LLM 파싱 결과는 헤딩 레벨을 자주 틀린다. 근본 원인은 **정보 손실**이다:

- PDF에서 "제목 아래 빈 줄이 있는지"가 소절(H3)과 라벨(H4)을 가르는 결정적 신호인데,
- 마크다운으로 변환되는 순간 그 시각적 여백 정보가 사라진다.
- 그래서 **텍스트만 보고 판별하면 원리적으로 틀릴 수밖에 없는** 케이스가 존재한다.

## 설계 해법 — 시각 검증 루프

텍스트로 부족한 판단을 **원본 PDF의 시각 신호로 되돌려 확정**한다.

1. PDF를 페이지별 이미지로 변환(`pdf2image`).
2. 실제 레이아웃을 눈으로 보고 "제목 아래 빈 줄 유무"를 판정.
3. 그 신호로 H3/H4를 확정한 뒤 마크다운을 교정.

핵심은 **결정 규칙의 우선순위를 명문화**한 것이다 — "H4 판단 순서"를 표보다 위에 둬서, 애매할 때 모델이 규칙을 뒤지지 않고 순서대로 적용하게 했다. 판단을 사람의 감이 아니라 **재현 가능한 절차**로 바꾼 것이 이 스킬의 요점이다.

## 상태 추적 — 재개 가능성

33개 장을 여러 세션에 걸쳐 처리하므로, 스킬 안에 **작업 로그**를 둬서 "어디까지 했는지 / 각 장에서 무슨 패턴을 교정했는지"를 기록한다. 덕분에:

- 중단 후 다른 세션에서 이어받아도 중복 없이 재개(idempotent re-entry).
- 장마다 다른 예외(보험업 별도 규칙, 시행일 문서 보류 등)를 잊지 않는다.

> 이 showcase 사본에서는 장별 장황한 변경내역을 대표 패턴 몇 개로 압축했다. 실제 운영본은 33개 장 전체의 개별 로그를 유지한다.

## 흔한 실패와 방지

| 실패 | 방지 장치 |
|------|-----------|
| PDF 안 보고 텍스트만으로 H3/H4 판단 | "반드시 PDF 시각 확인" 을 처리 순서 2단계에 못박음 |
| 일부 페이지만 확인 | "모든 페이지 확인" 명시 |
| 용어의 정의를 bold로 오변환 | 흔한 실수 표에 반례로 고정 |
| 부록 라벨을 헤딩으로 승격 | "줄 자체를 삭제" 규칙으로 노이즈 차단 |

## 이 스킬이 보여주는 것

정밀하고 반복적인 작업에서, **모델이 틀릴 수밖에 없는 지점을 식별하고(정보 손실), 그 지점만 외부 신호(PDF 이미지)로 보강하며, 판단을 재현 가능한 규칙·상태 추적으로 코드화**하는 에이전트 설계 접근.
