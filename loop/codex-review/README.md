# codex-review — 교차모델 검증 루프 (harness × loop)

Claude가 Plan → Execute로 짜낸 코드를 **다른 모델(Codex CLI)** 에게 독립 리뷰시켜 자기검증의 맹점을 메우는 Evaluate 서브루프. `/codex-review` 커맨드로 실행하며, diff 리뷰 → triage → 반영 → 재리뷰를 수렴할 때까지 돈다.

> 실제 구동에는 `codex` CLI 설치 + ChatGPT 구독 로그인(또는 API 키)이 필요하다. 이 쇼케이스에는 커맨드 본체(`command.md`)와 설계 노트만 담는다.

## 문제

Phase 3(Evaluate)의 기본 검증은 **Claude가 자기 코드를 자기가 본다**. 그런데 자기검증은 **같은 실패 모드를 공유**한다 — 같은 학습 분포, 같은 맹점. 자기가 낸 버그는 자기 눈에 잘 안 보인다. 테스트가 통과해도 "테스트가 놓친 결함"은 그대로 남는다.

→ **오류가 탈상관(decorrelated)된 독립 리뷰어**가 필요하다. 다른 모델은 Claude가 못 보는 다른 결의 버그를 잡는다.

## 왜 harness이면서 loop인가

- **harness**: Evaluate 단계에 "외부 교차리뷰"를 행동 계약으로 못박는다(전역 CLAUDE.md Phase 3). "리뷰를 붙이면 좋다"가 아니라 "비자명한 변경은 붙인다"로 고정.
- **loop**: diff 리뷰 → triage → 반영 → 재리뷰를 **수렴/상한까지 반복**하는 유한 루프. 사람이 매 라운드 개입하지 않는다.

## 두 개의 제어 게이트

- **독립성 게이트** — 리뷰어는 반드시 *다른 모델*(Codex)이고, diff만 주고 **read-only**로 부른다. 리뷰어가 코드를 못 고치니 자기검증이 유일 검증이 되지도 않고, 리뷰어가 멋대로 코드를 바꾸지도 못한다.
- **triage 게이트** — 어떤 finding도 **valid/invalid 판정 + 근거 없이는 반영 안 함**. 나쁜 지적을 맹목 반영해 코드가 널뛰는 것(review thrash)을 막는다.

## 각 장치가 막는 실패

| 위험 | 방어 |
|---|---|
| 자기검증 맹점 | 다른 모델(Codex) 독립 리뷰 |
| 위양성(없는 버그 조작) | 리뷰 계약의 **burden of proof** — 실패 증명 없으면 보고 금지 |
| 맹목 수용 → 코드 오염 | triage 게이트(valid만, 근거 필수) |
| 무한/진동 루프 | 라운드 상한 3 + invalid finding 재심 금지 |
| 파싱 실패를 조용히 통과 | JSON 스키마 강제 + 파싱 실패 시 **중단·보고**(통과 아님) |
| 스코프 크립 | 리뷰를 diff+성공기준으로 한정, 범위 밖 제안은 deferred |

## 리뷰 계약이 하는 일

Codex에 주는 프롬프트는 리뷰를 "부탁"이 아니라 **출력 계약**으로 못박는다(같은 repo `pr-code-review` 스킬과 같은 정신, 단 리뷰어가 다른 에이전트다):

- **적대적 + 입증책임**: "결함이 있다고 가정하되, 논리적 실패 증명 없이는 보고 금지" — 고무도장(과소 보고)과 위양성(과다 보고)을 동시에 차단.
- **JSON 스키마 강제**: severity / location / claim / why / suggestion — Claude가 기계적으로 triage 가능.
- **파싱 안정화**: 마크다운 펜스 금지 명시 + 스키마 밖 주석 → invalid JSON 방지.

## 이 루프가 보여주는 것

단일 에이전트의 자기검증 한계를 **모델 다양성(Codex) + 구조화된 리뷰 계약 + 근거 기반 triage + 유한 루프**로 넘어서는 설계. 리뷰어는 조언자일 뿐 결정자가 아니며, 반영의 최종 판단과 책임은 작성자(Claude)에게 남긴다.
