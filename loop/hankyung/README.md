# hankyung — 자율 스케줄 루틴 (loop engineering)

매일 아침 한국경제신문에서 주요 기사를 스크랩해 **Notion "뉴스 클리핑" DB에 자동 정리**하는 스케줄 루틴. Claude Code의 scheduled-task로 등록해, 사람 개입 없이 브라우징 → 선별 → 요약 → Notion 페이지 생성까지 수행한다.

> 이 showcase 사본에서 Notion `data_source_id`는 `<YOUR_NOTION_DATA_SOURCE_ID>` 플레이스홀더로 치환했다. 실제 사용 시 본인 DB의 data_source_id로 바꾼다.

## 문제

매일 반복되는 뉴스 클리핑은 (1) 사이트 접속 → (2) 중요 기사 선별 → (3) 원문 확인 → (4) 재구성 요약 → (5) 정해진 포맷으로 DB 기록, 이 다섯 단계가 매번 똑같다. 사람이 하면 지루하고, 단순 크롤러로는 "선별·요약·감상"이 안 된다. → **판단이 필요한 반복 작업을 자율 에이전트에 위임**한다.

## 자율성 설계

- **스케줄 실행**: 매일 아침 트리거. 사람이 시작 버튼을 누르지 않는다.
- **기준을 프롬프트로 위임**: "경제·산업·IT/AI·정치·사회 중 중요도 높은 2~4건, 단신·광고·인사 제외" — 어떤 기사를 고를지의 *판단 기준*만 주고 선택은 에이전트에 맡긴다.
- **원문 직접 접속 강제**: 헤드라인만 보고 요약하지 않도록 "반드시 원문 페이지에 접속해 확인"을 명시 → 환각·부정확 요약 방지.

## 멱등성 (중복 실행 방지)

스케줄 작업은 재시도·중복 트리거 위험이 있다. 그래서 **"작성 전, 오늘 날짜 페이지가 이미 있으면 새로 만들지 말 것"** 을 넣었다. 같은 날 두 번 돌아도 페이지가 중복 생성되지 않는다 — 자율 루틴의 안전장치.

## 출력 포맷 강제

결과 일관성을 위해 페이지 스키마를 고정한다:

- **제목**: `YY-MM-DD(요일)` — 정렬·검색 가능한 날짜 키.
- **속성**: 발견일(date), 분류(고정된 multi_select 목록에서만 선택).
- **본문 블록**: `제목 → 원문 링크 → 핵심 요약 불릿 → 1인칭 감상 초안`을 기사마다 반복.

특히 **1인칭 감상 초안**(`<span color="purple">`)은 의도적 설계다 — 에이전트가 완성된 의견을 내는 게 아니라, "~인 것 같다" 어투의 **초안**을 제시해 사용자가 나중에 다듬을 여지를 남긴다. 자동화가 사람의 판단을 대체하지 않고 **보조**하도록 경계를 그은 것.

## 이 루틴이 보여주는 것

단순 크론 잡이 아니라, **판단이 필요한 반복 작업을 (a) 스케줄로 자율화하고, (b) 선별 기준을 위임하되, (c) 멱등성으로 안전하게 만들고, (d) 출력 스키마로 결과를 일관되게** 만든 loop engineering 설계.
